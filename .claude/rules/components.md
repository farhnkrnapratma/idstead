# Components and styling

- `@idstead/ui` (`packages/ui/src`) — the design system, browser-safe and depending only on `@idstead/domain` (ESLint enforces this): `components/` (Button, IconButton, Dialog, ConfirmationDialog, Dropdown, ActionMenu, NavMenu (grouped link menu on `Dropdown`), form fields, Toast, Tooltip, DataTable, Pagination, EmptyState (pair it with a skeleton inside a `stableHeight` wrapper so the empty state keeps the skeleton's height), ErrorState, LoadingState, RefineImage (every content image and avatar: a sweep while loading and a short mosaic resolve once the image has loaded), GradientText, LoadingIndicator (the Material 3 shape-morph loading indicator every spinner uses; its keyframes are the `animate-loading-morph` and `animate-loading-spin` theme tokens in `global.css`), StatusBanner, StatsGrid, the shortcut badges and catalog, and `filter/` controls), `layout/` (PageMain, PageContainer, Section, FormSection), `stores/` (theme, toast, a11y, reading mode, scroll, shortcuts, filter/sort), `utils/` (`cn`, focus scope, popover positioning and shortcut attachment; browser storage keys use the `idstead_` prefix), `shortcuts.ts` (the keyboard shortcut engine and this site's key map: after the ctrl+space leader, arrow keys move, `G` then a letter goes to a page, single letters act on the current page, Shift+letter covers secondary actions and lists, Alt+letter blog-only actions; `tests/shortcuts.test.ts` fails when two bindings share a key), `types.ts`, and `styles/` (`global.css`, `tokens.css`). Import components and stores by path (`@idstead/ui/components/Button.svelte`) or through the `@idstead/ui` barrel; ui components `@reference "../styles/global.css"`.
- `@idstead/domain` (`packages/domain/src`) — pure TypeScript with no workspace, Svelte or SvelteKit imports: `formatters.ts`, `pluralize.ts`, `readTime.ts`, `slug.ts`, `pagination.ts`, `fieldValidation.ts`, `nameValidator.ts`, `sanitizeInput.ts`, `siteOrigin.ts`, `xml.ts`, `hash.ts`, `instance.ts`, `analytics.ts` (analytics providers and their validation), the public DTOs (`author.ts`, `blog.ts`, `legal.ts`) and the domain `types.ts` (`Section`, `Project`). `bun run check` type-checks it with strict `tsc`, and the Svelte apps list it in `ssr.noExternal`.
- `apps/web/src/lib/` — components used only by the public site: `components/` (SiteNav, the sticky navigation bar the root layout renders on every public page, SiteMeta, ProfileCard, ContentCard (the post and project card, with an optional banner; `contentCards.ts` maps posts and projects to its props) with ProjectMeta and ProjectLanguageTag, ResumeEntryList, SpotlightDialog with its data and logic in `components/spotlight/` (command catalogs, help catalog, icons, pure matching), SpotlightSearch, ConsentBanner, ResumeDownloadMenu, LegalPageLayout, PageActions (the "Copy page" split button and its menu on posts and legal pages), TableOfContents (the right-hand rail, with its geometry in `tocRail.ts`), …), `article/` (ArticleHeader, HelpfulBlock), `siteNavigation.ts` (the page links and the Connect, Legal and Feeds groups that both SiteNav and the footer render), `layout/` (FooterSection with one column per navigation group, and FooterSiteLink) and their stores and helpers. Import them as `#app/...` (each Svelte app's `package.json` maps `#app/*` to `./src/lib/*`; SvelteKit 3 has no `$lib`).
- `apps/admin/src/lib/` — admin-only code, imported as `#app/...`: `components/admin/` (PostEditor, AdminHome, AccountSettings, activity and chart components), the image upload components and processing pipeline (`process*.ts`, `workers/`), admin stores, session timeout, post save client and `mdrsPreview.ts`.
- `bun run lib-usage` shows which app reaches each remaining lib file; move a file into an app once only that app uses it and no shared lib file imports it.
- `packages/lib/src/components/` — the components both apps share (CommentThread, BrandIcon).
- `@mdrs/editor` (`packages/mdrs/editor/src`) — the Markdown editor. Import it only as `import { MarkdownEditor } from '@mdrs/editor'`; the shell composes `EditorViewBar` (tabs, settings, the optional `onImport` file button), `EditorToolbar`, `EditorCodeArea`, `EditorPreview` and `EditorStatusBar`, with pure helpers in `textEdits.ts`, `highlight.ts` and `preferences.svelte.ts`. It never imports server or data code: callers pass `render` (the admin uses `renderMdrsPreview` from `apps/admin/src/lib/mdrsPreview.ts`, which fetches live data from `/api/internal/admin/mdrs-data` and caches it for a minute) and the upload and import handlers.
- The page-structure primitives (PageMain, PageContainer, Section, FormSection) are in `@idstead/ui/layout/`. `PageMain` is the `<main id="main">` shell below the 3.5rem `SiteNav`: `variant="site"` (the default) fills the rest of the viewport, `variant="article"` also fixes posts and legal pages to it on large screens so the article and its table of contents scroll on their own, and `reading` drops the offset while reading mode hides `SiteNav`; use it instead of repeating the offsets. `Input` with `type="search"` draws a leading Lucide `Search` icon unless it has its own leading icon or slot.
- `packages/lib/src/article/ArticleMeta.svelte` — post metadata line shared by the web post page and the admin post list.
- Styling: Tailwind CSS 4 (via `@tailwindcss/vite`, no separate config file) plus `tokens.css` and `global.css` in `@idstead/ui/styles/` — component- and page-specific styling lives in each component/page's own `<style>` block or inline Tailwind classes.
- Colors: `tokens.css` declares only semantic roles, light in `@theme` and dark in `:root.dark`, and every value points at Tailwind's palette (`var(--color-mist-100)`, `color-mix(in oklab, var(--color-mist-950) 4%, transparent)`), never a hex or `rgb()` literal. Roles: `canvas`, `surface*`, `overlay`; text `fg`, `fg-secondary`, `fg-muted`, `fg-accent|success|warning|danger`; `on-accent`, `on-danger`; borders `line-subtle`, `line`, `line-strong`; `accent*`, `focus-ring`, `highlight`; status `info`, `success`, `warning`, `danger`, `discovery` with `-subtle` (and `danger-strong`); data scales `activity-*`, `report-*`, `calendar-*`. Markup uses their utilities (`text-fg-muted`, `bg-fg/5`), not palette classes or literals. Code that needs a concrete color (the manifest, `<meta name="theme-color">`, canvas, Mermaid) reads it through `themeToken()` (`@idstead/ui/themeColors.ts`), which resolves the token to hex. Email HTML, PDF exports, the QR export and GitHub language colors keep literal colors because they render outside the stylesheet.
- **Every page must reuse the existing shared components/layout primitives consistently** — never build a page-local one-off replacement for something that already exists. Run the `ui-consistency-check` skill (or the `ui-consistency-reviewer` agent) after touching any page or component to catch drift.

## Svelte MCP tooling

Claude Code can use the Svelte MCP server, which provides comprehensive Svelte 5 and SvelteKit documentation. Follow this workflow when working on Svelte or SvelteKit topics:

- Use `list-sections` first to discover available documentation sections. It returns titles, use cases, and paths.
- After `list-sections`, analyze the returned sections, especially `use_cases`, and use `get-documentation` to retrieve every section relevant to the task. The tool accepts one or multiple sections.
- Use `svelte-autofixer` whenever writing Svelte code, before presenting it to the user. Continue calling it until it returns no issues or suggestions.
- After completing code, ask the user whether they want a Svelte Playground link. Call `playground-link` only after the user confirms, and never call it when the code was written to project files.
